```sql
SELECT o.order_id
FROM lisanov_food."order" AS o
LEFT JOIN lisanov_food.payment AS p ON p.order_id = o.order_id
GROUP BY o.order_id
HAVING count(*) FILTER (WHERE p.status = 'успех') <> 1;
```

Ожидается пустой результат. Это запрос для повторной проверки; отдельный нативный вывод именно этого запроса в данном протоколе не заявляется.

В успешном тесте `add_product` передаётся `p_rating = NULL`: у нового блюда ещё нет отзывов (BR-9.7). Ненулевой рейтинг из примера E.1 противоречит этому правилу и в реализации отклоняется. Идентификаторы ресторана и категории сначала выбираются в переменные блока `DO`, затем передаются в `CALL`.
